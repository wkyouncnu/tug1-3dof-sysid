## 1. 좌표계 규약

### 1.1 두 프레임

| 프레임 | 정의 |
|---|---|
| 월드 (관성) | **NED** — x 북, y 동, z 하 |
| 바디 | **FRD** — x 선수, y 우현, z 하 |

**PX4 는 월드 NED · 바디 FRD 를 쓴다. 이는 Fossen / SNAME 규약과 동일하다.**
따라서 ULog 에서 읽은 값을 그대로 운동방정식에 넣을 수 있고 **부호 반전이 없다**.
(ROS/Gazebo 의 ENU 월드 + FLU 바디를 쓰는 파이프라인과 섞으면 sway·yaw 가 통째로 틀린다.
이 저장소는 PX4 데이터만 다룬다.)

### 1.2 상태 벡터

```
nu   = [u, v, r]ᵀ          바디 속도 (surge, sway, yaw rate)
eta  = [x, y, psi]ᵀ        월드 위치 / 선수방위
```

### 1.3 기구학

```
ẋ   = u cos(psi) − v sin(psi)
ẏ   = u sin(psi) + v cos(psi)
psï = r
```

행렬형:

```
eta_dot = R(psi) nu ,     R(psi) = [ cos psi  −sin psi  0 ]
                                   [ sin psi   cos psi  0 ]
                                   [    0         0     1 ]
```

### 1.4 월드 속도 → 바디 속도 (ULog 처리)

ULog 는 `vehicle_local_position.vx/vy/vz` 를 **월드 NED** 로 준다. 바디로 돌린다:

```
u =  v_N cos(psi) + v_E sin(psi)
v = −v_N sin(psi) + v_E cos(psi)
r =  vehicle_angular_velocity.xyz(3)      (이미 바디 FRD — 변환 불필요)
```

실제 구현은 `vehicle_attitude.q` 로 만든 전체 DCM 을 써서 roll/pitch 가 섞인 효과까지
반영한 뒤 수평성분을 취한다 (`ulog2run.m`).

## 2. 강체 운동방정식 (Fossen 3-DOF)

### 2.1 일반형

```
M nu_dot + C(nu) nu + D(nu) nu + d0 = tau
```

| 항 | 의미 |
|---|---|
| `M` | 질량/관성 행렬. **강체질량 + 부가질량을 합산한 유효질량** |
| `C(nu)` | 코리올리·원심력 (강체 + 부가질량분 합산) |
| `D(nu)` | 유체 감쇠. 선형항 + 2차(모듈러) 항 |
| `d0` | 상수 편향. 트림·정렬오차·잔류 외란을 흡수 |
| `tau` | 추진기 작용력/모멘트 `[tau_x, tau_y, tau_N]ᵀ` |

### 2.2 질량행렬

질량중심 x 방향 오프셋 `x_g` 를 허용하면

```
      [ m11   0    0  ]
M  =  [  0   m22  m23 ]  ,    m23 = m x_g + (부가질량 연성항)
      [  0   m23  m33 ]
```

- `m11 = m − X_u̇` : surge 유효질량. **선체질량 17.86 kg 에 고정했다** (§5.3 참조)
- `m22 = m − Y_v̇` : sway 유효질량
- `m33 = I_z − N_ṙ` : yaw 유효관성
- `m23` : sway–yaw 관성 연성. `m x_g` 와 부가질량 연성항을 분리할 수 없으므로 하나로 묶는다

`m11` 과 `m22` 는 **세 방정식에 동시에 나타난다**(§2.3 의 `C` 를 보라).
이것이 추력 스케일과 감쇠 스케일의 전역 축퇴를 부분적으로 깨는 유일한 구조적 장치다.

### 2.3 코리올리·원심력

`M` 이 위 형태일 때 반대칭(skew-symmetric) 코리올리 행렬은

```
         [      0            0       −m22 v − m23 r ]
C(nu) =  [      0            0           m11 u      ]
         [ m22 v + m23 r   −m11 u          0        ]
```

```
             [ −m22 v r − m23 r²        ]
C(nu) nu  =  [  m11 u r                 ]
             [ (m22 − m11) u v + m23 u r ]
```

**이 항들은 식별하지 않는다.** `m11, m22, m23` 이 정해지면 전부 결정된다.
이들을 빼면 선회·지그재그 구간이 통째로 틀린다. 반대로 임의 계수로 두면
감쇠항과 다중공선이 되어 식별이 무너진다.

### 2.4 감쇠 + 편향

실측으로 선정한 항 집합(`tug1_dyn.m` 과 일치):

```
surge:  Xu·u  + Xuu·|u|u + Xvv·|v|v + Xrr·|r|r + X0
sway :  Yv·v  + Yvv·|v|v + Yr·r    + Yrr·|r|r + Yvr·|v|r + Y0
yaw  :  Nr·r  + Nrr·|r|r + Nv·v    + Nvv·|v|v + Nuv·u v + Nvr·|v|r + Nur·u r + N0
```

- **2차항은 모듈러형 `|·|·`** 을 쓴다. 제곱형 `(·)²` 은 역방향에서 부호가 틀린다.
  이 선박은 역추력이 정추력의 78 % 이고 후진 기동이 데이터의 상당 부분이므로 중요하다.
- `Xvv`, `Xrr` : 선회 중 저항 증가(쌍동선 비대칭 유동)
- `Nuv`, `Nur` : 속도에 비례하는 조종 모멘트. 전형적인 Munk moment / 선회 저항 연성
- `X0, Y0, N0` : 상수 편향. 추력 비대칭·추진기 정렬오차·센서 바이어스를 흡수

### 2.5 최종 미분방정식

```
nu_dot  = M⁻¹ [ tau − C(nu) nu − D(nu) nu − d0 ]
eta_dot = R(psi) nu
```

6차 상태 `s = [u, v, r, x, y, psi]ᵀ`, 23개 파라미터

```
theta = [ m11, m22, m33, m23,
          Xu, Xuu, Xvv, Xrr, X0,
          Yv, Yvv, Yr, Yrr, Yvr, Y0,
          Nr, Nrr, Nv, Nvv, Nuv, Nvr, Nur, N0 ]
```

이 순서는 `tug1_model.m` 의 `ORD` 와 `tug1_dyn.m` 의 `p(1..23)` 과 **반드시** 일치한다.

## 3. 추진기와 추력배분

### 3.1 배치

X_b 가 선수방향, Y_b 가 우현방향(FRD)일 때

| 추진기 | 위치 | 작용방향 |
|---|---|---|
| `f₁` 좌현 후미 | `(−x_a, −d)` | `+X_b` |
| `f₂` 우현 후미 | `(−x_a, +d)` | `+X_b` |
| `f₃` 선수 | `(+l₃, 0)` | `+Y_b` (**횡방향 전용**) |

`d = 0.300 m`, `l₃ = 0.500 m`. 조향각은 없다 (고정 추진기).

### 3.2 배분 행렬

FRD 에서 yaw 모멘트는 `N = x·F_y − y·F_x` 다. 따라서

```
      [X]       [ 1    1    0  ]   [f₁]
tau = [Y]   =   [ 0    0    1  ] · [f₂]  =  T f
      [N]       [ d   −d    l₃ ]   [f₃]
```

`det T = 2d = 0.6 ≠ 0` — **정방·가역이다. 3-DOF 완전구동이고 중복이 없다.**
닫힌형 역해:

```
f₃ = Y
f₁ = X/2 + (N − l₃ Y) / (2d)
f₂ = X/2 − (N − l₃ Y) / (2d)
```

**후미 2기만 있는 부족구동 USV 는 `tau_y ≡ 0` 이므로 sway 를 `−u r` 원심결합으로만
간접 여기할 수 있다. 이 선박은 직접 줄 수 있다.** 이것이 하드웨어적 차별점이다.

### 3.3 순수 crabbing 의 실현 조건

`u ≈ 0, r ≈ 0, v ≠ 0` 을 유지하면 `Y_v`, `Y_|v|v`, `m22` 가 다른 자유도와 완전히
분리되어 식별된다. 단 선수 추진기가 `Y` 를 주면서 동시에 `l₃·Y` 의 yaw 모멘트를 만들므로
후미 2기가 그것을 상쇄해야 한다:

```
실현 조건:  |l₃ Y / (2d)| ≤ |f_min|
최대 횡력:  Y_max = min( f_max,  |f_min| · 2d / l₃ )
                 = min( 37.11,  29.41 × 0.6/0.5 ) = 35.3 N
```

**보유 데이터에는 순수 crabbing 기동이 없다.** 이것이 §5.2 공선성 한계의 직접적 원인이다.

### 3.4 T200 PWM-추력 곡선 (18.5 V)

제조사 공개 성능표에서 18.5 V 열만 추출해 균일격자로 재구성했다.

| 항목 | 값 |
|---|---|
| PWM 격자 | `1200 : 4 : 1800` µs (151점) |
| 데드밴드 | `[1476, 1528]` µs (14격자점, 추력 정확히 0) |
| 추력 범위 | **−29.4138 … +37.1093 N** |
| 2차 모델 적합도 | R² = 0.99973, RMSE = 0.266 N |

**비대칭이다.** 역추력이 정추력의 79 % 다. 이것이 §3.3 의 crabbing 진폭과
후진 기동의 모델링을 모두 제약한다.

Simulink 구현은 격자 벡터를 그대로 **1-D Lookup Table** 의 breakpoint/table 로 넣는다.
데드밴드가 표 자체에 0 으로 들어 있어 **별도 데드밴드 블록이 필요 없다.**
두 벡터가 모두 단조이므로 보간이 유효하다.

## 4. 로그의 `tau` 를 믿으면 안 되는 이유

### 4.1 온보드 지령 사슬 (Simulink 역공학 결과)

```
RC ch3 (surge), ch1 (yaw), ch5 (arm), ch7 (controller enable)
   ↓  [−1, 1] 정규화
   ↓  스틱 데드밴드 (surge ±0.10, yaw ±0.05)
tau_RC = [s_x, 0, s_N]            ← ★ Y 채널은 Constant 0 으로 하드와이어
   ↓  구간별 이득 (s_x < 0 ? ×56.66 : ×71.71 ;  s_N < 0 ? ×33.42 : ×37.18)
★ 여기까지가 로그의 taux / tauy / taun 이다 (배분 전 지령)
   ↓  daisy-chain 추력배분
      u3 = clamp(N / l₃, u3_min, u3_max)
      N_res = N − l₃ u3
      f₁ = X/2 + N_res/(2d),  f₂ = X/2 − N_res/(2d),  f₃ = u3
   ↓  n_i = sign(f_i)·sqrt(|f_i| / k(sign))      ← 로그의 motor1..3
   ↓  모터 데드밴드 게이트 ±33 rad/s  (⇔ |f| ≤ 0.40 N)
   ↓  n → PWM 룩업
   ↓  Saturation [1200, 1800]                     ← 로그의 spare_one/two/three
```

### 4.2 결정적 사실

**로그의 `tauy` 가 전 구간 정확히 0 이다.** 유효 144개 로그에서 `max|tauy_cmd| = 0.000e+00`.
조종기에 sway 스틱이 없어 `Y` 입력이 Constant 0 으로 고정되어 있다.

그 결과 추력배분의 `Y == 0` 분기가 **항상** 선택되고, 그 분기에서

```
f₃ = N / l₃   (선수 추진기가 포화하지 않는 동안)
```

이므로 **선수 추진기가 모든 기동에서 주 yaw 구동기로 동작한다.**
즉 `tau_y = f₃ = N/l₃ = 2 tau_N / (2 l₃ / ...)`, 구체적으로 `tau_y = 2 tau_N` (l₃ = 0.5 일 때)
가 성립한다. 로그의 `tauy = 0` 과 실제 작용 `tau_y ∈ [−29.4, +37.1] N` 은 완전히 다르다.

**⇒ 로그의 `taux/tauy/taun` 은 배분 전 지령이며 실제 작용력이 아니다.
작용력은 반드시 PWM 로부터 재구성해야 한다.**

### 4.3 작용력 재구성 (PWM 기준)

```
pwm   = clamp(spare_one/two/three, 1200, 1800)
f     = interp1(T200.pwm, T200.f, pwm, 'linear')
f(deadband) = 0                        % [1476, 1528] 명시적으로 0 처리
tau   = T f'
```

`motor1..3` (회전수) 경로로도 같은 계산을 할 수 있으나 PWM 과 최대 73 µs 어긋났다.
**PWM 이 ESC 가 실제로 받는 신호이므로 PWM 을 1차 기준으로 삼는다.**

## 5. 식별 정식화

### 5.1 출력오차(output-error) 최적화

**1-step 최소자승이 아니다.** 수용 기준이 완전재귀 롤아웃 궤적이므로 목적함수도 그래야 한다.
둘은 실제로 서로 다른 최적점을 준다.

창 `w` 에 대해 초기상태만 실측으로 주고 끝까지 적분한다:

```
s_hat(0) = [u_m(0), v_m(0), r_m(0), 0, 0, 0]ᵀ
s_hat(k+1) = RK4( s_hat(k), tau(k), tau(k+1), theta, h )     h = 0.02 s
```

RK4 중간스텝에서 `tau` 를 선형보간해 `tm = 0.5(t₁+t₂)` 값을 쓴다.

목적함수:

```
J(theta) = Σ_w Σ_k Σ_χ  w_χ ( s_hat_χ(k) − s_m_χ(k) )²
```

`w_χ` 는 각 채널을 데이터 표준편차로 정규화하는 가중이다 (`u, v, r` 과 `x, y, psi` 의
단위·크기 차이를 흡수). `lsqnonlin` (Levenberg–Marquardt / trust-region-reflective) 으로 푼다.

### 5.2 ★ 롤아웃 평가 시 바디 프레임 회전 — 틀리기 쉬운 지점

롤아웃을 `psi₀ = 0` 으로 시작하면 출력 `x, y` 는 **창 시작시점 바디 프레임 기준 변위**다.
반면 로그의 `x, y` 는 전역 NED 다. 비교 전에 실측을 창 시작 프레임으로 돌려야 한다:

```matlab
p0 = psi_m(a);
dX = x_m(a:b) − x_m(a);   dY = y_m(a:b) − y_m(a);
x_cmp =  cos(p0)·dX + sin(p0)·dY;
y_cmp = −sin(p0)·dX + cos(p0)·dY;
psi_cmp = psi_m(a:b) − p0;
```

**이 회전을 빼먹으면 5초 창 위치 RMSE 가 0.14 m 에서 4.06 m 로 뛴다.**
모델이 틀린 것처럼 보이지만 좌표계 불일치일 뿐이다.

### 5.3 축퇴와 그 대응

**문제.** 정상상태에서 `tau_u = X_u u + X_|u|u |u| u` 다. 추력이 실제로 k 배이면
`X` 계수가 전부 k 배로 나온다. 추력 스케일과 감쇠 스케일이 **정상상태에서 완전히 축퇴한다.**
궤적은 완벽히 맞는데 계수는 전부 틀린다.

**이 저장소에서 쓴 대응 3가지:**

1. **과도구간 포함.** `m u̇ = tau_u − D(u)u` 이므로 정지 출발에서 `u̇(0) = tau_u/m` 이다.
   **질량을 알면 추력이 절대값으로 결정된다.** 가감속·doublet 기동이 데이터에 들어 있다.
2. **`m11` 을 선체질량 17.86 kg 에 고정.** surge 부가질량을 0 으로 가정하는 것과 같다.
   쌍동선 세장체에서는 보수적이지만 허용 가능한 근사다. 이것이 스케일 기준점이 된다.
3. **`m11`, `m22` 의 방정식 간 공유.** `C(nu)nu` 를 통해 `m22` 가 surge 식에,
   `m11` 이 sway·yaw 식에 나타난다. 전역 스케일을 일률적으로 키우면 코리올리 항이
   깨지므로 축퇴가 부분적으로 해소된다.

**남은 한계.** 그럼에도 `m22` 가 선체질량의 3–6.7배, `m33` 이 기하학적 추정의 5–7배로 나온다.
부가질량만으로 설명되는 크기가 아니다. 추력 스케일 오차를 유효질량이 흡수한 것으로 보인다.
**근본 해결은 계류추력 시험(bollard pull)** — 로드셀에 계류해 PWM 을 스윕하고 `PWM → N` 을
직접 계측하는 것이다. 물에 띄우기 전에 할 수 있고 투자 대비 효율이 가장 높다.

### 5.4 속도 추정의 신뢰도

`v` 는 GPS 속도벡터와 IMU 자세로부터 나온 **추정기 출력**이다.
`v ≈ −V_g sin(beta)`, `beta = course − heading` 이므로 **heading 오차가 그대로 `v` 오차가 된다.**
저속일수록 `V_g` 가 작아 SNR 이 나빠진다. 식별 계수가 추정기 튜닝을 따라 움직일 수 있다는
뜻이며, 선박 쪽 문헌에서 `R = Q/SNR` 스윕으로 `N'_v` 의 **부호가 뒤집힌** 사례가 보고되어 있다.
이 저장소는 그 민감도 스윕을 수행하지 않았다 — 열린 한계로 기록한다.

## 6. 평가 지표

| 지표 | 정의 | 왜 보는가 |
|---|---|---|
| 채널별 RMSE | `rms(s_hat_χ − s_m_χ)` | 기존 문헌과 비교 가능한 기본 지표 |
| **ATE** | 위치오차 `‖(x,y)_hat − (x,y)_m‖` 의 집계. ★ **집계방식이 두 가지다 (아래)** | 궤적 전체의 평균적 어긋남 |
| 최종오차 | 창 마지막 시점 위치오차 | 누적 드리프트의 크기 |
| **ATE / 주행거리** | ATE ÷ 실측 경로길이 | 길이가 다른 기동을 공정하게 비교 |
| **ζ** | `mean( rmse_χ / std_χ )`, χ ∈ {u,v,r} | 단위가 다른 속도채널의 복합지표 |
| 지평 스윕 | H 초마다 재초기화한 창들의 집계 | 개루프 누적과 모델 자체 오차를 분리 |

### ★ ATE 집계방식이 두 가지다 — 표를 비교할 때 주의

| 구현 | 집계 | 성질 |
|---|---|---|
| `tug_eval.m` (`run_final.m` 의 표) | **점 단위 평균절대오차** — 모든 창의 모든 시점을 동등 평균 | **긴 창이 지배한다** |
| `run_slx_val.m` (Simulink 검증 표) | **창 단위 RMS** — 창마다 RMS 를 낸 뒤 창을 동등 평균 | 창 길이에 중립 |

같은 창 집합(val, 구간전체, `dist_w = 17.46 m`)에서 전자가 **3.165 m**, 후자가 **2.450 m**
로 나온다. **모순이 아니라 통계량이 다른 것이다.** 51 초짜리 지그재그 하나가 점 단위
집계를 끌어올린다. 수치를 인용할 때 어느 쪽인지 반드시 밝힌다 ([`RESULTS.md`](RESULTS.md) §0).

**지평 스윕이 중요한 이유.** 한 번만 초기화해 끝까지 가면 위치오차는 속도오차의 시간적분이므로
반드시 자란다. 이것은 모델 품질이 아니라 추측항법의 성질이다.
속도 RMSE 는 지평에 거의 무관하고(0.16/0.15/0.12 고정) 위치오차만 자란다는 사실을 보여야
"불안정이 아니라 적분 누적"이라는 주장이 성립한다.

## 7. 모델구조 후보와 선정

출력오차 최적화로 여러 항 집합을 비교했다 (`run_oe.m`).
최종적으로 두 구조를 남겼다.

| ID | 특징 |
|---|---|
| **D** | `m23` 음수 허용, `Nur` 활성. sway–yaw 관성 연성을 적극 사용 |
| **F3** | `m23` 양수, `Nur = 0`. 연성을 줄인 더 단순한 구조 |

성능이 거의 같다 (ATE 2.450 vs 2.513 m). **둘을 모두 유지하고 기본값을 F3 으로 둔다.**
구조가 다른데 궤적 성능이 같다는 것은 §5.3 의 식별성 한계를 직접 보여주는 증거다 —
**서로 다른 계수 집합이 같은 궤적을 만든다.** 따라서 계수의 물리적 해석보다
궤적 재현을 우선 목적으로 삼았다 (후속 강화학습의 운동모델이 목적이므로 합당하다).

**기각된 가설.** 선수 추진기의 유효추력이 전진속도에 따라 떨어진다는 가설
(`Ey1..3`, `dla`, `Ex1..2` 항 추가)은 실측으로 개선을 주지 못해 기각했다.
결과적으로 `e1 = tau_x`, `e2 = tau_y`, `e3 = tau_N` 이 정확히 성립하고,
**`l₃` 는 운동방정식에 나타나지 않는다 — 추력배분 전단에만 쓰인다.**

## 8. 무차원화를 쓰지 않은 이유

선박 조종 문헌의 표준인 **prime system** (SNAME 1950) 은 속도를 `U = √(u²+v²)` 로 나눈다.
이 선박의 데이터는 **제자리 선회(spin), 제위치 조정(reposition), 정지 출발** 이 큰 비중이고
그 구간에서 `U → 0` 이므로 **무차원 변수가 발산한다.**

대안은 `√(Lg)` 로 정규화하는 **bis system** (Norrbin 1970) 이나 고정 `U_ref` 스케일링이다.
그러나 이 저장소는 목적이 "궤적을 맞추는 운동모델"이고 단일 선박·단일 조건이므로
**무차원화의 이득이 없다.** 대신 목적함수에서 채널별 표준편차 정규화만 수행했다(§5.1).

## 9. roll / pitch 를 무시한 근거

3-DOF 근사의 타당성을 실측으로 확인했다 (`roll_check.m`).

| 항목 | 값 |
|---|---|
| `corr(phi, r)` | **−0.9036** |
| pitch 평균 / 최대 | +5.71° / 22.68° |

**roll 은 yaw rate 와 거의 공선이다.** 4번째 자유도를 넣어도 독립정보가 거의 없고
`r` 과 다중공선이 되어 식별을 해친다. 따라서 roll 은 무시할 수 있다.

**pitch 가 roll 보다 크다.** 추진기 작용점과 질량중심의 수직 오프셋이 가감속 중
pitch 모멘트를 만든다. 이것은 3-DOF 근사의 잔류 오차원으로 남으며,
가감속 기동(`forward_accdec`, ATE 3.0–4.0 m)이 상대적으로 불리한 이유의 일부로 보인다.

## 10. Simulink 등가성 조건

MATLAB 적분기(`tug_sim`)와 Simulink 모델이 **같은 모델**이어야 후속 강화학습 결과가
식별 단계의 평가와 연결된다. 일치 조건:

| 항목 | 설정 |
|---|---|
| 솔버 | **Fixed-step `ode4`** |
| 스텝 | `h = Ts = 0.02 s` |
| 입력 보간 | **`From Workspace` 의 Interpolate = on (ZOH 금지)** |

`tug_sim` 의 RK4 는 중간스텝에서 `tm = 0.5(t₁+t₂)` 의 입력을 선형보간해 쓴다.
Simulink 쪽 보간을 끄면(ZOH) 중간스텝 입력이 달라져 일치하지 않는다.

**검증 결과: 최대 편차 2.1e-14 m — 기계 정밀도.** (`check_slx.m`)

PWM 입력판은 **PWM** 을 보간한 뒤 비선형 룩업을 통과시키므로 원리적으로 완전히 같을 수 없다.
그 차이를 밸리데이션 31개 전 구간에서 측정한 결과 **최대 3.3 cm** 로, 궤적오차보다
두 자리 작다 (§RESULTS). 따라서 실용적으로 같은 모델로 취급한다.

## 11. 참고 규약 요약 (구현 시 체크리스트)

1. 좌표계 변환은 **파이프라인 초입에서 한 번만**. 이후 전 구간 NED/FRD.
2. 2차 감쇠는 **모듈러형 `|·|·`**. 제곱형은 역방향에서 부호가 틀린다.
3. 코리올리 항은 **반드시 넣고, 계수로 두지 않는다**. `M` 에서 결정된다.
4. 롤아웃 비교 전 **실측을 창 시작 바디 프레임으로 회전**한다(§5.2).
5. 로그의 `tau` 가 아니라 **PWM 에서 작용력을 재구성**한다(§4).
6. `To Workspace(Array)` 는 6×1 신호를 `[6 1 N]` 로 쌓는다 →
   `permute(squeeze(Y), [2 1])` 로 `N×6` 으로 되돌린다.
7. 1-D Lookup Table 은 3×1 벡터 입력에 **원소별로** 적용된다. Demux/Mux 가 필요 없다.
